Built with frameworks like React, Vue, Angular, or Svelte, SPAs rely on client-side routing to handle navigation without reloading the page. This means all routes (e.g., /about, /dashboard, /settings) are managed by JavaScript in the browser, not by the server. However, deploying an SPA to GitHub Pages—GitHub’s free static hosting service—can lead to a frustrating issue: direct navigation to deep links (e.g., visiting https://your-username.github.io/your-spa/about directly in the browser) results in a 404 Not Found error. Why? Because GitHub Pages, by default, is designed to serve static files. When it receives a request for /about, it looks for a physical file (e.g., about.html or about/index.html) in your repository. Since SPAs bundle all routes into a single index.html file, GitHub Pages can’t find the requested path and returns a 404. The solution? Configure GitHub Pages to redirect all traffic to index.html, allowing your SPA’s client-side router to take over and handle the route correctly. In this guide, we’ll walk through two reliable methods to achieve this, along with troubleshooting tips and best practices. Once loaded, JavaScript (via libraries like React Router, Vue Router, or Angular Router) intercepts navigation events (e.g., clicking a link) and dynamically updates the page content without reloading the browser. The URL in the address bar updates (e.g., from / to /about), but this is managed client-side—no request is sent to the server. How GitHub Pages Serves Content# GitHub Pages is a static hosting service, meaning it serves files exactly as they exist in your repository. When a user navigates to a URL like https://your-username.github.io/your-spa/about, GitHub Pages: Checks for a file named about.html in the root directory. If not found, checks for a directory named about with an index.html inside (about/index.html). If neither exists, it returns a 404 Not Found error. Since SPAs don’t have physical files for routes like /about (all content is in index.html), direct navigation to these routes triggers a 404. Prerequisites# Before diving into the configuration, ensure you have the following: A GitHub repository containing your SPA. Your SPA is built (e.g., npm run build for React/Vue, producing a build/ or dist/ folder with index.html and assets). GitHub Pages is enabled for your repository. To enable it: Go to your repo on GitHub → Settings → Pages. Under "Build and deployment," select the source (e.g., main branch, docs/ folder, or gh-pages branch). Save your settings. GitHub will deploy your site to https://.github.io// (or https://.github.io/ for user/organization sites). Your SPA uses client-side routing (e.g., React Router, Vue Router, Angular Router). Step-by-Step Configuration Methods# We’ll cover two proven methods to redirect all traffic to index.html on GitHub Pages. Choose the one that best fits your workflow. Method 1: Use a 404.html File to Capture and Redirect Requests# GitHub Pages automatically serves a 404.html file when a requested path doesn’t exist. We’ll leverage this to capture 404 errors and redirect them to index.html, where your SPA’s router can handle the route. How It Works:# When a user navigates to a non-existent route (e.g., /about), GitHub Pages serves 404.html. The script in 404.html captures the requested path (e.g., /about) and redirects to index.html, appending the path as a query parameter (?url=%2Fabout, where %2F is the encoded /). Your SPA will now load index.html and can use the url query parameter to navigate to the correct route. Step 2: Update Your SPA to Handle the Redirect# Once index.html loads, your SPA needs to read the url query parameter and navigate to the corresponding route. Below are examples for popular frameworks: Example 1: React (with React Router v6+)# In your root component (e.g., App.js), use useEffect and React Router’s useNavigate to handle the redirect: import { useEffect, useLocation } from 'react-router-dom'; function App() { const location = useLocation(); const navigate = useNavigate(); useEffect(() => { // Parse the "url" query parameter from the URL const searchParams = new URLSearchParams(location.search); const redirectUrl = searchParams.get('url'); if (redirectUrl) { // Navigate to the captured path and clear the query parameter searchParams.delete('url'); const newSearch = searchParams.toString() ? `?${searchParams.toString()}` : ''; navigate(`${redirectUrl}${newSearch}`, { replace: true }); } }, [location, navigate]); return ( {/* Your routes (e.g., } />) */} ); } export default App; Example 2: Vue (with Vue Router v4+)# In your root component (e.g., App.vue), use onMounted and Vue Router’s useRouter to handle the redirect: Example 3: Angular (with Angular Router)# In your root component (e.g., app.component.ts), use ngOnInit to handle the redirect: import { Component, OnInit } from '@angular/core'; import { ActivatedRoute, Router } from '@angular/router'; @Component({ selector: 'app-root', templateUrl: './app.component.html', }) export class AppComponent implements OnInit { constructor(private route: ActivatedRoute, private router: Router) {} ngOnInit(): void { // Parse the "url" query parameter this.route.queryParams.subscribe((params) => { const redirectUrl = params['url']; if (redirectUrl) { // Navigate to the captured path and clear query parameters this.router.navigate([redirectUrl], { replaceUrl: true }); } }); } } Method 2: Use Jekyll (GitHub Pages' Built-In Static Site Generator)# GitHub Pages natively supports Jekyll, a static site generator. However, Jekyll cannot solve the SPA deep linking problem on its own. Jekyll can only set permalinks for pages it generates—it cannot intercept requests for non-existent paths (like /about) and serve index.html for them. To handle SPA routing on GitHub Pages, you still need the 404.html redirect method described in Method 1. Jekyll's configuration is useful for other site features, but deep link handling requires server-side configuration that GitHub Pages provides through 404.html. The page should load without a 404, and your SPA should render the /about route. Test the back button: Navigate to /about, then click "Back"—it should return to the previous page correctly. Troubleshooting Common Issues# Issue 1: 404.html Not Redirecting# Cause: 404.html is not in the correct directory. Fix: Ensure 404.html is in the root of your GitHub Pages source (e.g., docs/, gh-pages branch, or root of main). Issue 2: SPA Not Handling the url Query Parameter# Cause: Your SPA’s router isn’t parsing the url parameter correctly. Fix: Double-check the code in Step 2 (e.g., React/Vue examples) for typos. Use console.log(redirectUrl) to verify the parameter is being captured. Issue 3: Base Path Issues (Project Sites)# Cause: For project sites (e.g., username.github.io/repo-name/), the redirect URL may be missing the base path. Fix: In 404.html, use window.location.origin + window.location.pathname.split('/')[1] to include the repo name. For example: // In 404.html const basePath = window.location.pathname.split('/')[1]; // e.g., "repo-name" window.location.href = `${window.location.origin}/${basePath}/index.html?url=${encodeURIComponent(path)}`; Issue 4: GitHub Pages Not Rebuilding# Cause: GitHub Pages may cache old versions of your site. Fix: Force a rebuild by pushing an empty commit: git commit --allow-empty -m "Force rebuild GitHub Pages" git push Conclusion# Direct navigation issues in SPAs hosted on GitHub Pages stem from GitHub's static file-serving behavior. By using the 404.html redirect method, you ensure your SPA's client-side router handles routing, delivering a seamless user experience. The 404.html method is the recommended solution for SPAs on GitHub Pages, as it works reliably and scales to dynamic routes.
